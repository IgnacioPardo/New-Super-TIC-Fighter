# Controller input verification

Menus use fixed standard buttons: Cross/A (0) confirms, Circle/B (1) goes back, and Options/Start (9) opens pause. Combat bindings remain configurable. Menu navigation prefers the D-pad or the dominant left-stick direction and repeats after a short delay. Controller detection and last normalized input are exposed through `InputManager.getControllerStatus()`.

Standard browser mappings pass through unchanged. The fallback only handles a recognized DualSense/DualSense Edge with a nonstandard mapping and the macOS HID layout of 14 buttons and 10 axes. Its mapping follows [Chromium's macOS MapperDualSense](https://chromium.googlesource.com/chromium/src/+/7d1e648a5f/device/gamepad/gamepad_standard_mappings_mac.mm). Unknown layouts remain unmodified.

Run `STF_APP_URL=http://127.0.0.1:4173 pnpm e2e:controllers` against the running application. This uses injected controller data in isolated Chromium: standard and raw HID DualSense movement, pause, disconnect, different-device quarantine and same-device reclaim. The menu-to-match exercise verifies visible controller focus after mouse use, confirm/back, automatic practice fighter assignment, movement, pause/resume, native select/range settings and actual Web Audio source starts. Both scripts exercise the complete application and its worker; they do not instantiate isolated input adapters.

These are simulated browser inputs, not physical Bluetooth/USB controller certification. A connected macOS device is not sufficient evidence that Arc exposes it through the Gamepad API. Physical verification must check the live controller status, actual button/stick activity, menu navigation and assigned fighter movement in the user's focused Arc session.

Physical check on 2026-10-11: macOS HID and Apple GameController both enumerated the connected Bluetooth DualSense while Arc initially returned no devices, including on an independent page polling `navigator.getGamepads()` without game code. An Arc-specific macOS Game Controllers customization enabled **Increase controller compatibility**, preserving Default controls. After the owner fully restarted Arc, the independent page detected the controller. This sequence does not establish whether compatibility, restarting, or both resolved exposure. A separate native, unmodified Chromium observation also detected `DualSense Wireless Controller (STANDARD GAMEPAD)`, 18 buttons and 4 axes. The owner then confirmed **menus and gameplay both work** in the updated application on Arc, after being asked to exercise D-pad/Cross navigation, practice, movement/jump and Options pause. This is physical owner verification, separate from injected automated coverage.

If Arc reports no controller despite macOS showing it connected: first press a controller button with the page focused. On this Mac, enabling the Arc-specific compatibility option followed by restarting Arc restored detection. The option is reversible in System Settings → Game Controllers → DualSense → Arc; disable it or remove only the Arc customization. [Apple documents the compatibility mechanism](https://developer.apple.com/documentation/gamecontroller/understanding-game-controller-backward-compatibility).
